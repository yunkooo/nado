# 영어 독해 노트 MVP 설계

작성일: 2026-06-08
상태: 사용자 검토용 초안

## 1. 요약

`nado`는 한국인을 위한 영어 독해 보조 서비스다. 웹은 Next.js로 만들고, 모바일 앱은 Expo React Native로 만들며, 데스크톱 앱은 Tauri로 웹 UI를 재사용해 만든다. 백엔드는 Railway에 배포하는 API 서버를 중심으로 두고, 인증과 데이터베이스는 Supabase Auth/Postgres를 사용한다. 사용자가 영어 한 문장 또는 짧은 문단을 입력하면, 앱은 항상 아래 순서의 학습 결과를 제공한다.

1. 자연스러운 한국어 번역
2. 번역 포인트
3. 단어 hover 저장을 포함한 문장별 영어 구조 분석
4. 우선 저장 추천 단어/숙어/표현

이 제품은 일반 번역기가 아니다. 사용자가 ChatGPT에 "번역해줘", "문법도 분석해줘", "중요 단어도 뽑아줘" 같은 프롬프트를 매번 쓰지 않아도, 앱이 미리 정해진 좋은 학습 흐름을 자동으로 적용하는 것이 핵심 가치다. 이것이 사용자가 굳이 이 웹사이트를 여는 가장 큰 이유가 되어야 한다.

첫 버전은 짧은 입력에 집중한다. 긴 글 분석, 공식문서 리더, 브라우저 확장, 유료 플랜, 사용자 개인 OpenAI API key 연결은 MVP 이후 확장으로 둔다.

MVP는 웹 프론트엔드 포트폴리오와 앱 출시 경험을 모두 보여줄 수 있게 모노레포로 구성한다. 웹은 데스크톱/모바일 브라우저를 지원하는 Next.js 반응형 웹앱으로 만들고, 모바일 앱은 WebView wrapper가 아닌 Expo React Native 네이티브 화면으로 구현한다. 데스크톱 앱은 Tauri로 웹 UI를 감싸되, 별도 오프라인 기능은 MVP 이후로 둔다. PWA는 선호하지 않으므로 범위에서 제외한다.

## 2. 제품 포지셔닝

앱은 이렇게 느껴져야 한다.

> 영어 문단이 내 독해 노트로 바뀐다.

앱은 이렇게 느껴지면 안 된다.

> 그냥 텍스트 입력창이 있는 일반 AI 채팅 화면이다.

핵심 차별점은 편리함과 일관성이다.

- 사용자는 영어 텍스트만 입력한다.
- 앱이 어떤 분석이 필요한지 대신 결정한다.
- 사용자는 프롬프트를 고민하지 않고도 항상 같은 품질의 독해 분석을 받는다.
- 분석 결과는 별도 모드 선택 없이 하나의 기본 독해 flow로 제공한다.
- 저장한 단어와 표현은 개인 단어장에 쌓인다.
- 복습은 시험이 아니라 가벼운 플래시카드처럼 느껴진다.
- 시각적 톤은 AI 도구처럼 깔끔한 생산성 앱 느낌을 지향하되, 읽기 편한 학습 도구로 느껴져야 한다.
- 서비스명 `nado`는 "나도 영어 문장을 읽고 이해할 수 있다"는 뉘앙스를 줄 수 있어 MVP 이름으로 사용한다.

## 3. MVP 목표

- 로그인 없이 영어 한 문장 또는 짧은 문단을 분석할 수 있게 한다.
- 사용자가 별도 프롬프트를 작성하지 않아도 정해진 독해 분석 flow를 제공한다.
- 자연스러운 한국어 번역을 가장 먼저 보여준다.
- 왜 그렇게 번역되는지 설명한다.
- 영어 문장을 한국인 학습자가 이해하기 쉬운 구조로 나눠 보여준다.
- 유용한 단어/숙어/표현을 추천하되 자동 저장하지 않는다.
- 단어 저장, 단어장, 복습 기능은 Google 로그인 후 사용할 수 있게 한다.
- 저장한 단어/숙어/표현을 관리하는 단어장을 제공한다.
- 정답/오답 채점 없는 플래시카드 복습을 제공한다.
- OpenAI API 비용을 보호하기 위해 입력 길이 제한, 서버 검증, 조정 가능한 사용량 제한, 저비용 모델 선택을 적용한다.
- 데스크톱 앱은 Tauri 개발 환경에서 실행 가능한 온라인 앱으로 제공한다.

## 4. MVP에서 제외할 것

- 긴 문서 전체 분석
- 공식문서 리더 모드
- 브라우저 확장 또는 사이드 패널
- PWA 설치형 앱
- Capacitor 기반 WebView wrapper 앱
- React Native WebView로 웹앱만 감싸는 앱
- 사용자 개인 OpenAI API key 연결
- 유료 플랜, 크레딧, 결제
- 간격 반복 학습
- 정답/오답 채점
- 음성 입력 또는 말하기 연습
- 전체 분석 히스토리 저장
- 단어장 항목에 사용자의 원문 영어 문장 저장
- 데스크톱 앱의 오프라인 단어장, 로컬 DB, 로컬 AI 분석

## 5. 기술 스택과 앱 구조

MVP는 모노레포로 구성한다.

```text
nado/
  apps/
    web/        # Next.js 웹앱
    mobile/     # Expo React Native 앱
    desktop/    # Tauri 데스크톱 앱
    api/        # Railway에 배포할 백엔드 API 서버
  packages/
    shared/     # 공통 타입, API schema, validation, 유틸
  supabase/     # Supabase local config와 migration
```

### 5.1 웹앱

웹앱은 Next.js로 구현한다. 데스크톱과 모바일 브라우저를 모두 지원하는 반응형 UI를 제공한다. 분석 화면, 단어장, 복습 기능을 웹에서도 사용할 수 있어야 한다.

웹 포트폴리오에서 보여줄 핵심은 다음과 같다.

- Next.js 기반 제품 구현
- 로그인 전/후 사용자 흐름
- AI 분석 결과의 구조화된 렌더링
- 단어장 CRUD
- 플래시카드 복습 인터랙션
- 입력 제한, 로딩, 에러, 빈 상태 처리
- 모바일 반응형 UI

### 5.2 모바일 앱

모바일 앱은 Expo React Native로 구현한다. 앱은 WebView로 웹앱을 그대로 감싸지 않고, 분석 화면, 단어장 화면, 복습 화면을 React Native 컴포넌트로 만든다.

MVP 모바일 앱 목표는 Expo 개발 환경에서 실행 가능한 앱이다. TestFlight, Google Play internal testing, App Store, Google Play 실제 출시는 MVP 이후 확장으로 둔다.

모바일 앱 포트폴리오에서 보여줄 핵심은 다음과 같다.

- Expo React Native 앱 구조
- 앱스토어 출시를 고려한 화면 구성
- 모바일 단어장과 복습 UX
- 네이티브 터치 인터랙션
- 앱 환경의 Google 로그인 흐름
- 향후 클립보드, 공유, 푸시 알림 같은 네이티브 기능 확장 가능성

### 5.3 데스크톱 앱

데스크톱 앱은 Tauri로 구현한다. MVP에서는 웹 UI를 재사용하는 온라인 데스크톱 앱으로 두고, 로컬 DB, 오프라인 단어장, 파일 시스템 기반 문서 저장은 MVP 이후 확장으로 둔다.

데스크톱 앱 포트폴리오에서 보여줄 핵심은 다음과 같다.

- 웹 UI를 데스크톱 앱으로 배포하는 구조
- 웹, 모바일, 데스크톱이 같은 백엔드 API를 공유하는 설계
- 데스크톱 앱에서도 분석, 단어장, 복습 흐름을 사용할 수 있는 일관된 제품 경험
- 향후 클립보드, 글로벌 단축키, 로컬 캐시 같은 데스크톱 기능 확장 가능성

### 5.4 공통 패키지

웹, 모바일 앱, 데스크톱 앱은 UI를 모두 동일하게 공유하지 않는다. 대신 공통 패키지에서 데이터 계약과 핵심 로직을 공유한다. 데스크톱 앱은 웹 UI를 재사용하지만, API schema와 validation은 다른 클라이언트와 같은 shared package 기준을 따른다.

공유 대상:

- API 요청/응답 타입
- AI 분석 결과 schema
- 문장별 분석 `sentences`와 끊어 읽기 `chunks` schema
- 단어장 항목 타입
- 입력 길이와 기본 validation 규칙
- 단일 기본 분석에 필요한 공통 렌더링 규칙
- 공통 에러 코드와 메시지 키

이 구조는 웹 프론트엔드 실력, React Native 앱 개발 경험, 데스크톱 앱 배포 경험을 함께 보여주기 위한 선택이다. Capacitor나 React Native WebView보다 개발량은 늘어나지만, 포트폴리오에서는 웹, 모바일, 데스크톱 클라이언트와 서버 경계를 각각 제대로 설계했다는 점이 더 분명하게 드러난다.

### 5.5 백엔드/API/DB 확정 구조

백엔드는 별도 API 서버를 두고 Railway에 배포한다. 인증과 데이터베이스는 Supabase Auth/Postgres를 사용한다. 로컬 개발은 Supabase CLI와 Docker 기반 로컬 Supabase 개발 서버를 사용하고, 운영 환경은 Cloud Supabase 프로젝트를 사용한다.

확정 구조:

```text
Web / Expo Mobile / Tauri Desktop
        ↓
Railway Backend API
        ↓
Supabase Auth + Postgres
        ↓
OpenAI API
```

역할:

- `apps/api`: 분석 API, 단어장 API, 인증 검증, 사용량 제한, OpenAI API 호출을 담당한다.
- Supabase Auth: Google 로그인과 사용자 인증을 담당한다.
- Supabase Postgres: 사용자, 단어장, 사용량 제한 데이터를 저장한다.
- Supabase local development: Docker 기반 로컬 Supabase 환경에서 schema와 migration을 개발한다.
- Cloud Supabase: 운영 환경의 인증과 데이터베이스를 담당한다.
- Railway: 백엔드 API 서버를 배포하고 OpenAI API key와 서버 환경변수를 안전하게 보관한다.

이 구조를 선택한 이유:

- 웹, 모바일, 데스크톱이 같은 API 계약을 공유한다.
- OpenAI API key를 클라이언트에 노출하지 않는다.
- 비로그인/로그인 사용자별 사용량 제한을 서버에서 일관되게 처리할 수 있다.
- Supabase Auth/Postgres로 로그인과 데이터 저장을 빠르게 구현하면서도, API 서버를 통해 백엔드 설계 경험을 보여줄 수 있다.
- 로컬 Supabase와 Cloud Supabase를 migration으로 관리하면 개발/운영 환경 차이를 줄일 수 있다.

### 5.6 백엔드 세부 결정 항목

아래 항목들은 확정 구조 안에서 구현 계획 단계에 구체화한다.

- 인증 세부 구현:
  - Google 로그인은 제품 요구사항으로 유지한다.
  - 웹 세션, 모바일 앱 토큰 저장, 데스크톱 앱 토큰 저장, 로그아웃, 토큰 만료 처리를 구체화한다.
- DB/ORM:
  - Supabase migration을 기본으로 사용한다.
  - 서버에서 Supabase client, Postgres client, Drizzle 중 무엇으로 DB에 접근할지는 구현 계획 단계에서 고른다.
- API 책임 범위:
  - `apps/api`가 분석, 단어장, 인증 검증, 사용량 제한의 중심이 된다.
  - 웹, 모바일 앱, 데스크톱 앱이 직접 DB 계층에 접근하지 않고 API 서버를 통해 접근한다는 원칙은 유지한다.
- 사용량 제한 저장 위치:
  - IP/userId별 분석 횟수를 Supabase Postgres의 별도 테이블에 저장할지, Railway 서버 캐시와 병행할지 결정한다.

### 5.7 구현 우선순위

가장 우선시되는 것은 웹앱이며, 그중에서도 분석 화면을 가장 먼저 구현한다. MVP 구현은 백엔드 API와 Next.js 웹앱의 분석 화면을 먼저 완성한 뒤, 같은 API schema와 shared package를 바탕으로 단어장, 복습, Expo React Native 앱, Tauri 데스크톱 앱 순서로 확장한다.

권장 순서:

1. `packages/shared`의 공통 타입/schema/validation 정의
2. Railway 배포를 전제로 한 `apps/api` 백엔드 기반 구축
3. Next.js 웹앱의 분석 화면 구현
4. Next.js 웹앱의 단어장과 복습 흐름 구현
5. Expo React Native 앱의 분석, 단어장, 복습 흐름 구현
6. Tauri 데스크톱 앱에서 웹 UI와 공통 API 흐름 연결
7. 웹, 모바일, 데스크톱의 공통 API 계약 검증

## 6. 사용자 흐름

### 6.1 분석 흐름

1. 사용자가 분석 화면을 연다.
2. 영어 한 문장 또는 짧은 문단을 입력한다.
3. 입력값을 trim 했을 때 비어 있으면 분석 버튼은 비활성화된다.
4. 입력은 최대 500자까지만 가능하다. 초과 붙여넣기나 추가 입력은 받지 않는다.
5. 사용자가 분석을 실행한다.
6. 서버가 입력값을 다시 검증한다.
7. 서버가 AI 분석 API를 호출한다.
8. 결과는 아래 순서로 표시된다.
    - 전체 자연스러운 한국어 번역
    - 전체 번역 포인트
    - 문장별 분석
    - 저장 추천 단어/숙어/표현
9. 사용자는 문장별 분석 안의 원문 단어를 hover, focus, tap해서 뜻을 확인하고 저장할 수 있다.
10. 로그인하지 않은 상태라면 Google 로그인을 안내한다.
11. 로그인 후 선택한 단어/숙어/표현이 저장된다.

### 6.2 단어장 흐름

1. 사용자가 Google로 로그인한다.
2. 단어장 화면을 연다.
3. 저장한 단어/숙어/표현 목록을 확인한다.
4. 각 항목에는 아래 정보를 보여준다.
   - 단어/숙어/표현
   - 타입
   - 한국어 뜻과 짧은 설명
   - 저장 날짜
5. 사용자는 항목을 삭제할 수 있다.

이미 저장된 단어/숙어/표현을 다시 저장하는 경우 새 항목을 만들지 않는다. 같은 사용자, 같은 `term`, 같은 `type`의 항목이 있으면 기존 항목에 뜻과 설명을 병합하고 `updatedAt`을 갱신한다. 이렇게 하면 같은 표현이 여러 맥락에서 다른 의미로 쓰일 수 있다는 점을 단어장 안에서 함께 볼 수 있다.

단어장 화면은 관리 화면이다. 뜻을 기본적으로 가리지 않는다.

### 6.3 복습 흐름

1. 사용자가 복습 화면을 연다.
2. 복습 방향을 선택한다.
   - 영어 → 한국어
   - 한국어 → 영어
3. 앱이 단어장 항목 중 하나를 랜덤으로 선택한다.
4. 카드는 문제 쪽만 보여준다.
5. 사용자가 카드를 클릭하면 정답을 보여준다.
6. 사용자가 다음 버튼을 누르면 다음 항목으로 넘어간다.
7. 사용자가 끝내기 버튼을 누르면 복습을 종료한다.
8. MVP에는 정답/오답 채점이 없다.
9. MVP에서는 별도 가중치, 점수, 복습 기록 없이 단순 랜덤으로 진행한다.
10. 저장 항목이 1개뿐이면 같은 항목 반복을 허용한다.

## 7. 화면

MVP 화면은 웹, 모바일 앱, 데스크톱 앱에서 제공한다. 웹은 반응형 UI로 만들고, 모바일 앱은 React Native 컴포넌트로 구현하며, 데스크톱 앱은 Tauri에서 웹 UI를 재사용한다. 세 플랫폼 모두 입력, 분석 실행, 결과 확인, 단어 저장, 플래시카드 복습이 편해야 한다. UI 톤은 깔끔한 AI 생산성 도구와 읽기 편한 학습 도구 사이에 둔다.

웹과 데스크톱 앱 내비게이션은 사이드바를 기본으로 한다. Expo React Native 앱은 `분석`, `단어장`, `복습`을 중심으로 한 하단 탭 내비게이션을 기본으로 한다.

### 7.1 분석 화면

첫 화면이다. 로그인 없이 사용할 수 있다.

주요 요소:

- 하단 고정 영어 입력창
- `421 / 500` 형태의 글자 수 표시
- 분석 버튼
- 분석 결과 섹션
- 상단 로그인 상태 표시

웹 분석 화면은 Codex 앱이나 ChatGPT처럼 결과 영역이 위에 있고, 입력 composer가 화면 하단에 고정되는 구조를 기본으로 한다. 사용자는 하단 입력창에 영어 문장이나 짧은 문단을 붙여넣고 바로 분석을 실행한다. 분석 결과는 상단의 대화/문서 영역에 누적된다.

MVP에서는 분석 모드 선택을 제공하지 않는다. 사용자가 옵션을 고르지 않아도 앱이 하나의 기본 분석 흐름을 자동으로 적용한다. 이는 사용자가 ChatGPT에 매번 "번역해줘, 문법도 분석해줘, 단어도 뽑아줘"라고 쓰지 않아도 되는 제품 가치와 맞닿아 있다.

하단 composer는 다음 요소를 포함한다.

- 오른쪽의 글자 수 표시
- 분석 실행 버튼

MVP composer에는 아직 용도가 정해지지 않은 `+` 보조 액션 버튼을 두지 않는다. 이후 파일 첨부, URL 분석, 예문 불러오기처럼 명확한 기능이 생길 때만 추가한다.

결과 섹션:

1. 전체 자연스러운 한국어 번역
2. 전체 번역 포인트
3. 문장별 분석
4. 저장 추천 단어/숙어/표현

전체 자연스러운 한국어 번역은 입력 문장이 여러 개일 때 문장 단위로 줄바꿈해서 표시한다. 한 문장 번역이 끝나면 다음 문장 번역은 다음 줄에 보여준다. 이렇게 하면 긴 문단에서도 번역 결과를 다시 읽기 쉽고, 하단의 문장별 분석과 대응시키기도 쉽다.

전체 번역은 사용자가 빠르게 의미를 확인하는 요약 영역이다. 이 서비스의 핵심 사용 가치는 문장별 분석과 단어 저장에 있으므로, 전체 번역은 과도하게 큰 폰트나 넓은 공간을 차지하지 않게 한다. 시각적 무게는 문장별 분석과 단어 hover 저장 흐름에 더 둔다.

전체 번역 포인트는 번역문을 다시 설명하는 긴 섹션이 아니다. 자연스러운 번역을 이해하는 데 필요한 핵심 이유만 짧게 보여준다. 예를 들어 직역하면 어색한 부분, 한국어에서는 생략하거나 바꾸는 표현, 문장 전체의 뉘앙스, 문단의 논리 흐름을 1~3개 bullet로 제공한다. 세부 구조와 문법 설명은 문장별 분석에서 다룬다.

문장별 분석은 입력된 문장을 나누어 하단에 문서형 흐름으로 보여준다. 카드 테두리를 기본으로 고집하지 않는다. 각 문장 분석은 여백, 타이포그래피, 얇은 구분선으로 구분하고, 필요한 경우에만 작은 보조 박스나 hover box를 사용한다. 각 문장 분석에는 원문 안의 끊어 읽기 표시, 끊어 읽기 단위별 직역, 문장 전체의 자연스러운 번역, 쉬운 구조 설명, 필요한 문법 포인트를 담는다. 끊어 읽기는 별도 제목이나 목록으로 먼저 설명하지 않고, 각 영어 chunk와 그 아래 직역을 하나의 시각적 덩어리로 묶어 자막처럼 보여준다. chunk 사이에는 포인트 컬러의 `/` slash를 넣어 끊어 읽기 지점을 표시한다. chunk 내부 영어 문장과 직역은 줄바꿈하지 않는다. 공간이 부족하면 가로 스크롤을 만들지 않고 chunk 블록 전체가 다음 줄로 내려간다. AI는 한 chunk가 너무 길어 화면을 밀어내지 않도록 의미 단위가 유지되는 선에서 더 짧게 끊는다. slash는 사용자가 문장을 어느 지점에서 나누어 읽으면 좋은지 알려주는 시각적 표시이며, 오류나 경고처럼 보이지 않게 사용한다. slash 단위별 직역은 영어 어순과 의미를 따라가며 "이 덩어리가 무슨 뜻인지"를 보여주는 독해 보조 정보다. 문장 전체의 자연스러운 번역은 그 아래에서 한국어답게 정리된 최종 의미로 제공한다. `that`이 명사절을 이끄는지, `before + -ing`가 시간 표현을 만드는지처럼 해석에 직접 도움이 되는 영어 문법은 문장별로 짧게 설명한다. 각 문법 포인트는 대상 표현, 문법 이름, 쉬운 설명을 분리해서 보여준다. 초보자도 이해할 수 있도록 `주어`, `동사`, `목적어` 같은 문법 용어만 던지지 않고, "누가/무엇을 한다/어떤 내용을 덧붙인다"처럼 쉬운 역할 설명을 함께 제공한다.

문법 포인트의 대상 표현과 문법 이름은 서로 떨어져 보이거나 줄바꿈되어 다른 항목처럼 보이지 않게 한 줄 라벨로 표시한다. 설명 문장은 오른쪽에서 자연스럽게 줄바꿈될 수 있다.

문장별 분석 예시는 단어 hover 저장 같은 특정 기능을 보여줄 때도 해당 문장의 기본 분석을 생략하지 않는다. 사용자가 일부 문장만 자세히 분석되고 다른 문장은 단어 저장만 가능한 것처럼 오해하지 않게 한다.

문장별 분석 카드에서는 원문에 포함된 모든 영어 단어를 각각 선택할 수 있게 보여준다. 웹과 Tauri 데스크톱 앱에서는 문장 안의 단어에 마우스를 올리면 hover box로 한국어 뜻, 품사, 해당 문맥에서의 의미, `+ 저장` 액션을 보여준다. 키보드 사용자를 위해 단어에 focus가 갔을 때도 같은 box를 보여준다. 모바일 웹과 Expo React Native 앱에서는 hover가 없으므로 단어를 tap하면 같은 정보를 popover 또는 bottom sheet로 보여준다.

사용자가 어떤 단어를 클릭하거나 tap하더라도 한국어 뜻, 품사, 해당 문맥에서의 의미, `+ 저장` 액션을 볼 수 있어야 한다. `the`, `a`, `to`, `with`처럼 쉬워 보이는 단어도 사용자가 원하면 저장할 수 있다. 표현/숙어는 모든 단어 저장 구조 위에 앱이 추가로 묶어주는 저장 후보로 제공한다. 저장은 추천 단어에만 제한하지 않는다. 추천 단어/표현은 앱이 우선 저장하면 좋다고 강조하는 항목일 뿐이며, 사용자는 추천되지 않은 단어도 직접 저장할 수 있어야 한다.

초기 구현에서는 결과 섹션을 기본적으로 펼쳐서 보여준다. 접힘/펼침, 탭, 섹션 밀도 조정은 실제 화면을 보고 결정한다.

추천 단어/표현은 화면을 복잡하게 만들지 않도록 가볍게 표시한다. 칩 또는 작은 행 형태로 보여주고, 각 항목에는 `+ 저장` 액션을 둔다. 이 섹션 이름은 사용자가 저장 가능 범위를 오해하지 않도록 `우선 저장 추천`처럼 표현한다.

분석 입력창 근처에는 "입력한 문장은 AI 분석을 위해 전송되며, 단어장에는 원문 문장을 저장하지 않습니다."라는 안내를 제공한다.

### 7.2 단어장 화면

Google 로그인이 필요하다.

주요 요소:

- 저장한 단어/숙어/표현 목록
- 각 항목의 모든 뜻과 설명
- 빈 상태 안내
- 삭제 액션

검색과 필터는 MVP에 포함하지 않는다.

단어장 목록에서는 의미 개수만 보여주지 않는다. 저장된 `meanings`의 모든 뜻과 설명을 기본적으로 펼쳐서 보여준다. 한 단어에 여러 뜻이 쌓이면 같은 행 안에서 줄 단위로 모두 표시한다.

### 7.3 복습 화면

Google 로그인이 필요하다.

주요 요소:

- 복습 방향 선택
- 플래시카드
- 클릭해서 정답 보기
- 다음 버튼
- 끝내기 버튼
- 단어장이 비어 있을 때의 안내

복습 카드는 MVP에서 간단하게 구현한다. 영어 → 한국어 방향에서는 앞면에 단어/표현을 보여주고, 뒷면에 대표 뜻과 설명을 보여준다. 한국어 → 영어 방향에서는 앞면에 대표 뜻을 보여주고, 뒷면에 단어/표현과 설명을 보여준다. 한 항목에 여러 의미가 있으면 첫 번째 의미를 대표 뜻으로 사용하고, 뒷면에서 나머지 의미도 함께 보여준다.

## 8. 인증

MVP는 Google 로그인만 지원한다.

Google 로그인은 제품 요구사항으로 확정한다. 웹, Expo React Native 앱, Tauri 데스크톱 앱에서 세션/token을 어떻게 발급, 저장, 검증할지는 구현 계획 단계에서 구체화한다.

분석은 로그인 없이 사용할 수 있다. 아래 기능은 로그인이 필요하다.

- 단어/숙어/표현 저장
- 단어장 보기
- 단어장 항목 삭제
- 복습 시작

이 방식은 첫 사용 장벽을 낮추면서, 장기적으로 쌓이는 사용자 데이터는 계정에 안전하게 연결한다.

## 9. API 설계

### 9.1 `POST /api/analyze`

목적:

영어 한 문장 또는 짧은 문단을 분석한다.

인증:

필요 없음.

요청 예시:

```json
{
  "text": "I was wondering if you could help me with this issue."
}
```

MVP에는 별도 분석 모드 값이 없다. 웹, Expo React Native 앱, Tauri 데스크톱 앱은 같은 schema를 기준으로 화면을 렌더링한다.

번역 관련 필드:

- `translation`: 자연스러운 한국어 번역.
- `translationExplanation`: 번역 포인트. 자연스러운 번역을 이해하는 데 필요한 핵심 이유를 짧게 제공한다.

`sentences`는 문장별 상세 분석 영역에 사용한다. 각 문장의 `tokens`는 원문 단어를 클릭 가능한 단위로 렌더링하기 위해 사용한다. 각 문장의 `chunks`는 slash로 끊어 읽는 단위이며, `literalTranslation`으로 해당 덩어리의 직역을 제공한다. `structure`는 전체 입력에서 가장 중요한 구조를 요약해서 보여주는 보조 섹션으로 사용한다.

`vocabularyItems`는 사용자가 원문에서 직접 선택해 저장할 수 있는 항목 목록이다. 원문에 포함된 모든 영어 단어는 반드시 포함한다. 표현/숙어는 앱이 추가로 묶어주는 저장 후보로 함께 포함할 수 있다. 각 항목은 한국어 뜻과 문맥상 의미를 포함한다. `vocabularySuggestions`는 `vocabularyItems` 중 앱이 우선 저장 대상으로 추천하는 항목이다. 즉, 추천 목록에 없더라도 `vocabularyItems`에 있는 항목은 사용자가 저장할 수 있다.

검증:

- text가 없으면 거절한다.
- trim 후 빈 문자열이면 거절한다.
- 500자를 넘으면 거절한다.
- 명확히 학습 입력으로 보기 어려운 값은 가능한 범위에서 로컬 규칙으로 거절한다.
- 애매한 경우에는 AI가 `not_analyzable` 상태를 반환하게 한다.

로컬 규칙 예시:

- 알파벳 비율이 지나치게 낮은 입력
- 같은 글자가 과도하게 반복되는 입력
- 공백이나 문장부호 없이 긴 랜덤 문자열처럼 보이는 입력
- 대부분이 기호 또는 숫자인 입력

분석 가능 응답 예시:

```json

    "sentences": [
      {
```

목적:

로그인한 사용자의 단어장 목록을 반환한다.

인증:

필요함.

응답 예시:

```json

    {

          "createdAt": "2026-06-08T00:00:00.000Z"
        }
      ],
      "createdAt": "2026-06-08T00:00:00.000Z",
      "updatedAt": "2026-06-08T00:00:00.000Z"
    }
  ]
}
```

### 9.3 `POST /api/vocabulary`

목적:

로그인한 사용자의 단어장에 단어/숙어/표현을 저장한다.

인증:

필요함.

요청 예시:

```json
{
  "term": "wonder if",
  "type": "phrase",
  "meaning": "~인지 궁금하다",
  "note": "정중한 질문이나 요청에서 자주 쓰입니다."
}
```

검증:

- `term`은 필수다.
- `type`은 `word` 또는 `phrase`여야 한다.
- `meaning`은 필수다.
- `note`는 선택이지만 저장을 권장한다.
- MVP에서는 원문 영어 문장을 저장하지 않는다.

저장 동작:

- 같은 사용자에게 같은 `term`과 같은 `type`의 항목이 없으면 새 항목을 만든다.
- 같은 사용자에게 같은 `term`과 같은 `type`의 항목이 있으면 새 항목을 만들지 않고 기존 항목에 뜻/설명을 병합한다.
- 이미 같은 뜻/설명이 들어 있다면 중복으로 추가하지 않는다.
- 병합이 발생하면 `updatedAt`을 갱신한다.

### 9.4 `DELETE /api/vocabulary/:id`

목적:

단어장 항목 하나를 삭제한다.

인증:

필요함.

권한:

삭제하려는 항목은 로그인한 사용자의 항목이어야 한다.

### 9.5 복습 데이터

MVP에는 별도 복습 API가 필요하지 않다.

프론트엔드는 `GET /api/vocabulary`로 단어장 목록을 가져온 뒤, 로컬에서 플래시카드 선택을 처리한다. 이후 복습 기록, 정답/오답, 간격 반복을 넣을 때 별도 API를 추가한다.

## 10. AI 분석 구현

MVP에서는 서비스 운영자의 OpenAI API key를 사용한다. API key는 서버에만 보관하고, 브라우저 코드에 노출하지 않는다.

서버는 사용자 입력과 고정된 개발자 지시문을 함께 OpenAI Responses API로 보낸다. 응답은 자유 텍스트가 아니라 Structured Outputs를 사용해 안정적인 JSON 구조로 받는다. 그래야 프론트엔드가 문자열을 억지로 파싱하지 않고, `translation`, `translationExplanation`, `sentences`, `sentences[].chunks`, `structure`, `vocabularyItems`, `vocabularySuggestions` 같은 필드를 안정적으로 렌더링할 수 있다.

관련 공식 문서:

- OpenAI Text generation guide: https://platform.openai.com/docs/guides/text?api-mode=responses
- OpenAI Structured Outputs guide: https://platform.openai.com/docs/guides/structured-outputs
- OpenAI Responses API reference: https://platform.openai.com/docs/api-reference/responses
- OpenAI API pricing: https://openai.com/api/pricing/

프롬프트 동작 원칙:

- 한국인 영어 학습자에게 설명한다.
- 설명은 한국어로 작성한다.
- 자연스러운 한국어 번역을 가장 먼저 둔다.
- 전체 번역을 먼저 제공한 뒤, 하단에서 문장별 분석을 제공한다.
- 전체 결과에는 별도 직역 섹션을 만들지 않는다.
- 문장별 분석에서는 slash로 나눈 `chunks`마다 직역을 제공한다.
- 구조 분석은 초보자가 이해할 수 있게 끊어 읽기와 쉬운 역할 설명 중심으로 작성한다.
- 번역, 번역 포인트, 구조 분석, 문법 포인트, 단어/표현 추천을 모두 제공한다.
- 설명은 한 문장 또는 500자 이내 짧은 문단을 학습하기에 충분한 밀도로 제공하되, 과도한 리포트처럼 느껴지지 않게 제한한다.
- `vocabularyItems`에는 사용자가 직접 저장할 수 있는 원문 속 모든 영어 단어와 각각의 뜻을 반드시 제공한다. 표현/숙어는 추가 저장 후보로 함께 제공할 수 있다.
- `vocabularySuggestions`에는 `vocabularyItems` 중 우선 저장할 가치가 높은 단어/숙어/표현만 추천한다.
- 의미 없는 입력은 `not_analyzable`로 반환한다.
- 위험하거나 악의적인 텍스트에 대해서는 학습 목적의 번역/해석 범위를 넘는 예문 생성이나 확장을 피한다.

단일 기본 분석 동작:

- 목적은 번역기보다 학습에 도움이 되는 기본 해석 흐름을 자동으로 제공하는 것이다.
- 입력된 모든 문장을 다룬다.
- 각 문장의 자연스러운 한국어 번역을 제공한다.
- 원문 문장 안에 `/` slash로 끊어 읽기 지점을 표시한다.
- slash로 나뉜 각 chunk에는 직역을 제공한다.
- 문장별 핵심 구조와 문법 포인트를 균형 있게 설명한다.
- 전체 문단 기준 핵심 문법 포인트는 1~3개 중심으로 제공한다.
- 단어/표현 추천은 3~5개 중심으로 제공한다.
- 설명은 문장별로 너무 길지 않게 유지한다.

## 11. 데이터 모델

### 11.1 사용자

사용자는 인증 제공자가 관리한다.

앱에서 필요한 최소 필드:

- `id`
- `email`
- `name`
- `image`
- `createdAt`

### 11.2 단어장 항목

필드:

- `id`
- `userId`
- `term`
- `type`: `word` 또는 `phrase`
- `meanings`: 뜻과 설명 목록
- `createdAt`
- `updatedAt`

`meanings` 항목 필드:

- `meaning`
- `note`
- `createdAt`

단어장 항목의 논리적 중복 기준은 같은 `userId`, 같은 정규화된 `term`, 같은 `type`이다.

MVP에서는 사용자의 원문 영어 문장을 저장하지 않는다.

### 11.3 분석 단어 항목

분석 단어 항목은 AI 분석 응답 안에서만 사용하는 임시 데이터다. 사용자가 저장하기 전까지 DB에 저장하지 않는다.

필드:

- `key`: `tokens[].vocabularyKey`와 연결되는 정규화된 키
- `term`: 원문에 표시할 단어 또는 표현
- `baseForm`: 저장할 때 기준이 되는 기본형
- `type`: `word` 또는 `phrase`
- `partOfSpeech`: 품사. 표현이면 `null`일 수 있다.
- `meaning`: 기본 한국어 뜻
- `contextMeaning`: 현재 문장에서의 의미와 쓰임
- `saveLabel`: 저장 버튼이나 단어장에 표시할 이름

분석 화면은 `vocabularyItems`를 사용해 사용자가 원문 속 모든 영어 단어를 직접 저장할 수 있게 한다. 표현/숙어 항목은 단어 항목과 별도로 추가 저장 후보로 제공한다. `vocabularySuggestions`는 이 항목들 중 우선 저장을 권장하는 subset으로 취급한다.

## 12. 사용량과 비용 정책

MVP는 서비스 운영자의 OpenAI API key로 제한된 무료 분석을 제공한다.

정확한 일일 사용량 제한 숫자는 이 설계에서 확정하지 않는다. MVP가 실제로 동작한 뒤 비용, 응답 속도, 사용 패턴을 보고 결정한다.

구현은 아래 값을 설정으로 조정할 수 있어야 한다.

- 비로그인 사용자 분석 제한
- 로그인 사용자 분석 제한
- 제한 기준 시간 단위, 예: 일 단위

이 값들은 코드에 고정된 비즈니스 상수로 박지 않고, 환경변수 또는 서버 설정으로 조정할 수 있게 한다.

비용 보호 장치:

- 500자 입력 제한
- 빈 입력일 때 분석 버튼 비활성화
- 서버 측 입력 검증
- 명확히 이상한 입력에 대한 로컬 차단
- 애매한 악성/무의미 입력에 대한 AI-level `not_analyzable` 처리
- MVP용 저비용 모델 선택
- 향후 동일 입력 반복 분석 캐싱 검토

향후 비용 전환 또는 수익화 선택지:

- 유료 플랜
- 크레딧 시스템
- 사용자 개인 API key 연결

위 항목들은 MVP에 포함하지 않는다.

## 13. 에러 처리

- 빈 입력:
  - 분석 버튼을 비활성화한다.
- 500자 초과 입력:
  - 초과 입력은 받지 않는다.
  - 서버에서도 초과 요청을 거절한다.
- 의미 없는 입력:
  - "영어 문장으로 분석하기 어려워요. 한 문장 또는 짧은 문단을 입력해 주세요."라고 안내한다.
- OpenAI API 실패:
  - "분석 중 문제가 발생했어요. 잠시 후 다시 시도해 주세요."라고 안내한다.
- 구조화된 응답 형식이 잘못된 경우:
  - 서버에서 1회 재시도한다.
  - 두 번째 시도도 실패하면 분석 실패 안내를 보여준다.
- 비로그인 사용자가 단어 저장을 누른 경우:
  - Google 로그인을 안내한다.
- 단어장이 비어 있는 경우:
  - "먼저 분석 화면에서 단어/표현을 저장해 주세요."라고 안내한다.
- 복습 항목이 1개뿐인 경우:
  - 같은 항목 반복을 허용한다.
- 분석 입력 개인정보 안내:
  - "입력한 문장은 AI 분석을 위해 전송되며, 단어장에는 원문 문장을 저장하지 않습니다."라고 안내한다.

## 14. 테스트와 검증

MVP 검증 범위:

- 빈 입력이면 분석 버튼이 비활성화되는지 확인한다.
- 입력이 500자를 넘을 수 없는지 확인한다.
- 클라이언트를 우회해도 서버가 500자 초과 입력을 거절하는지 확인한다.
- 명확한 이상 입력이 분석 불가 응답을 받는지 확인한다.
- 분석 요청에 별도 분석 모드 값이 포함되지 않는지 확인한다.
- 응답이 단일 기본 분석 schema를 유지하는지 확인한다.
- `sentences[].chunks[].literalTranslation`이 끊어 읽기 단위별 직역 문자열로 반환되는지 확인한다.
- 번역, 번역 포인트, 구조 분석, 문법 포인트, 단어/표현 추천이 제공되는지 확인한다.
- 전체 번역이 먼저 표시되고, 하단에 문장별 분석 영역이 표시되는지 확인한다.
- 구조 분석이 끊어 읽기와 쉬운 역할 설명을 포함하는지 확인한다.
- 분석 입력창 근처에 AI 분석 전송 및 원문 미저장 안내가 표시되는지 확인한다.
- 분석 결과가 정해진 순서로 표시되는지 확인한다.
- 추천 단어/표현이 자동 저장되지 않는지 확인한다.
- 원문 단어/표현 각각의 뜻과 문맥상 의미가 표시되는지 확인한다.
- 추천 단어/표현이 아니어도 사용자가 직접 선택한 단어/표현을 저장할 수 있는지 확인한다.
- 단어 저장 시 Google 로그인이 필요한지 확인한다.
- 로그인한 사용자가 단어/표현을 저장할 수 있는지 확인한다.
- 이미 저장한 단어/표현을 다시 저장하면 새 항목이 아니라 기존 항목의 `meanings`에 병합되는지 확인한다.
- 단어장 목록이 현재 사용자 항목만 보여주는지 확인한다.
- 사용자가 자기 단어장 항목을 삭제할 수 있는지 확인한다.
- 사용자가 다른 사용자의 단어장 항목을 삭제할 수 없는지 확인한다.
- 웹, 모바일 앱, 데스크톱 앱이 같은 API schema를 사용하는지 확인한다.
- 모바일 앱에서 분석 화면, 단어장, 복습 화면이 React Native 컴포넌트로 동작하는지 확인한다.
- 데스크톱 앱에서 Tauri로 웹 UI가 실행되고 같은 백엔드 API를 호출하는지 확인한다.
- 복습 모드에 로그인이 필요한지 확인한다.
- 복습 시작 전에 방향을 선택할 수 있는지 확인한다.
- 복습 카드가 대표 뜻을 기준으로 간단히 동작하고, 여러 의미가 있을 때 뒷면에서 함께 표시되는지 확인한다.
- 플래시카드를 클릭하면 정답이 보이는지 확인한다.
- 다음 버튼을 누르면 다음 랜덤 항목이 나오는지 확인한다.
- 끝내기 버튼으로 복습 모드를 종료할 수 있는지 확인한다.

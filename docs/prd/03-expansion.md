# PRD 03. 확장 후보

이 문서는 MVP 이후 검토할 아이디어만 정리한다. 항목이 있다는 이유만으로 구현이 확정된 것은 아니다.

## 우선순위 원칙

확장 기능은 아래 질문에 답할 수 있을 때 별도 PRD로 승격한다.

1. 실제 사용자가 반복해서 겪는 문제인가?
2. 영어 독해 학습에 직접 도움이 되는가?
3. AI와 운영 비용을 감당할 방법이 있는가?
4. 개인정보 저장 범위가 명확한가?
5. 어느 플랫폼부터 제공할지 정했는가?

## 후보 목록

| 후보                | 해결하려는 문제                             | 구현 전 확인할 것                          |
| ------------------- | ------------------------------------------- | ------------------------------------------ |
| 긴 글 분석          | 200자를 넘는 글을 나누어 읽기 어렵다        | 분석 단위, 비용 상한, 결과 탐색 UI         |
| 공식문서 리더       | 기술 문서에서 필요한 구간을 학습하기 어렵다 | URL 처리 범위, 코드 블록 구분, 크롤링 정책 |
| 브라우저 확장       | 복사하고 앱을 여는 과정이 번거롭다          | 선택 문장 전달, 로그인, 스토어 정책        |
| 앱스토어 출시       | Expo 앱을 실제 사용자에게 배포하고 싶다     | OAuth, 개인정보 안내, QA, store 심사       |
| Desktop 생산성 기능 | 데스크톱 앱만의 장점이 부족하다             | 단축키, clipboard, 권한, 오프라인 범위     |
| 단어장 검색·필터    | 저장 항목이 많아지면 찾기 어렵다            | 검색 기준, word/phrase 필터, 정렬          |
| 예문 생성           | 저장한 표현을 다른 문맥에서 연습하기 어렵다 | 생성 비용, 캐시, 품질 검증                 |
| 간격 반복           | 장기 기억을 위한 복습 일정이 없다           | 정답 기록, 다음 복습일, 데이터 모델        |
| 분석 히스토리       | 이전 분석을 다시 볼 수 없다                 | 원문 저장 동의, 삭제 정책, 보관 기간       |
| 유료 정책           | 운영 비용이 사용량과 함께 커진다            | 무료 범위, 결제, 환불, 비용 측정           |

## 보류 원칙

- MVP 운영과 크로스 플랫폼 검증이 끝나기 전에는 기능 수를 늘리지 않는다.
- 원문 저장이 필요한 기능은 사용자 동의와 삭제 정책을 먼저 만든다.
- AI 비용이 늘어나는 기능은 제한, 캐시, 실패 처리까지 함께 설계한다.
- 구현이 결정되면 이 문서에 세부 요구사항을 더하지 않고 별도 PRD와 Issue를 만든다.

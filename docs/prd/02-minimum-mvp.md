# PRD 02. 최소 MVP

상태: 핵심 기능 구현 완료, 운영·실기기 검증 진행 필요

## 해결하려는 문제

번역기는 뜻을 알려주지만 문장을 읽는 방법까지 일관되게 설명하지 않는다. 범용 AI는 도움이 되지만 사용자가 매번 번역, 문법, 단어 추출 요청을 직접 작성해야 한다.

`nado`는 아래 학습 흐름을 제품 안에 고정한다.

```text
영어 입력 → AI 분석 → 단어 저장 → 단어장 → 복습
```

## MVP 목표

- 로그인 없이 200자 이내 영어 문장이나 짧은 문단을 분석한다.
- 자연스러운 번역, 번역 포인트, 문장별 분석, 저장 추천을 같은 순서로 제공한다.
- 로그인 사용자는 단어와 표현을 저장·조회·삭제할 수 있다.
- 저장 항목으로 간단한 플래시카드 복습을 할 수 있다.
- Web, Mobile, Desktop에서 같은 API와 제품 규칙을 사용한다.

## 이번 범위가 아닌 것

- 긴 문서 분석과 공식문서 리더
- 브라우저 확장과 PWA
- 분석 히스토리와 원문 저장
- 정답·오답 기록과 간격 반복 학습
- 결제, 크레딧, 유료 플랜
- 사용자의 개인 AI API key 연결

확장 후보는 [PRD 03](03-expansion.md)에서 관리한다.

## 사용자 흐름

### 1. 분석

1. 사용자가 영어를 입력하고 모델을 선택한다.
2. 클라이언트와 서버가 빈 값, 200자 초과, 지원하지 않는 문자를 검증한다.
3. API 서버가 선택된 모델에 따라 OpenRouter 또는 OpenAI를 호출한다.
4. 앱은 번역 → 번역 포인트 → 문장별 분석 → 저장 추천 순서로 결과를 보여준다.
5. 새 분석 결과는 입력문과 함께 사용자별 session 상태로만 유지한다.

### 2. 단어 저장과 단어장

1. 비로그인 사용자가 저장을 누르면 Google 로그인을 안내한다.
2. 로그인 사용자가 단어 또는 표현을 저장한다.
3. 같은 사용자·term·type이 이미 있으면 새 뜻과 설명을 기존 항목에 합친다.
4. 단어장에서는 저장된 뜻을 확인하고 항목을 삭제할 수 있다.
5. 사용자의 원문 문장은 단어장에 저장하지 않는다.

### 3. 복습

1. 영어 → 한국어 또는 한국어 → 영어 방향을 선택한다.
2. 저장 항목의 문제 면을 먼저 보여준다.
3. 사용자가 답을 열고 다음 카드로 이동한다.
4. MVP에서는 점수와 정답·오답 기록을 저장하지 않는다.

## 플랫폼 범위

| 플랫폼    | MVP 범위                                      |
| --------- | --------------------------------------------- |
| Web       | 분석, 로그인, 저장, 단어장, 삭제, 복습        |
| Mobile    | Web과 같은 학습 흐름을 React Native UI로 제공 |
| Desktop   | Web과 같은 학습 흐름을 Tauri 앱으로 제공      |
| Storybook | Web/Desktop 컴포넌트의 주요 상태 확인         |

## API 계약

| Method   | Path                  | 인증 | 역할                     |
| -------- | --------------------- | ---- | ------------------------ |
| `GET`    | `/health`             | 없음 | API 상태 확인            |
| `GET`    | `/ready`              | 없음 | Supabase 연결 준비 확인  |
| `POST`   | `/api/analyze`        | 선택 | 영어 입력 분석           |
| `GET`    | `/api/vocabulary`     | 필요 | 내 단어장 조회           |
| `POST`   | `/api/vocabulary`     | 필요 | 단어 저장 또는 의미 병합 |
| `DELETE` | `/api/vocabulary/:id` | 필요 | 내 단어장 항목 삭제      |

세부 필드는 문서에 복사하지 않고 `packages/shared/src/index.ts`의 schema를 기준으로 한다.

## 인증과 사용자 데이터

- MVP 로그인 방식은 Google OAuth다.
- 분석은 익명 사용자도 사용할 수 있다.
- 단어 저장, 단어장, 삭제, 복습은 로그인이 필요하다.
- 계정이 바뀌면 이전 사용자의 분석 상태와 진행 중 요청 결과를 새 계정에 적용하지 않는다.
- 단어장 접근은 사용자 access token과 Supabase RLS 경계를 따른다.

## 사용량과 비용

- AI provider key는 API 서버에서만 사용한다.
- 개발 단계의 분석 제한 기본값은 익명·로그인 모두 `0`이며, `0`은 무제한을 뜻한다.
- `.env.example`도 로컬 개발을 위해 두 제한값을 `0`으로 둔다.
- 운영에서는 비용 정책을 정한 뒤 `NADO_ANONYMOUS_DAILY_ANALYSIS_LIMIT`와 `NADO_AUTHENTICATED_DAILY_ANALYSIS_LIMIT`를 반드시 명시한다.
- `0`은 사용량을 기록하되 요청을 차단하지 않는 무제한 설정이고, `1`~`2147483647`은 실제 일일 상한이다. 예를 들어 익명 `3`, 로그인 `20`을 사용할 수 있지만 이는 정책 예시이지 코드 기본값이 아니다.

## 실패 처리

- 입력 오류는 API 호출 전에 이해하기 쉬운 메시지로 안내한다.
- 분석할 수 없는 입력은 일반 서버 오류와 구분한다.
- 네트워크와 AI provider 요청은 제한 시간을 넘기면 중단한다.
- 구조화 응답이 잘못되면 같은 전체 시간 예산 안에서 한 번 재시도한다.
- 저장·삭제 중 계정이 바뀌면 이전 요청 결과를 현재 화면에 반영하지 않는다.

핵심 기능은 구현되어 있다. 플랫폼별 운영·실기기 검증 증거는 [릴리스 준비도](../release-readiness.md)에서 확인하고, 실제 작업 상태는 Notion `프로젝트` 티켓에서 관리한다.
